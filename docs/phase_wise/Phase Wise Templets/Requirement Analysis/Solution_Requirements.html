Solution Requirements

1. Introduction

This document specifies the complete set of Functional and Non-Functional Requirements for the ShopEZ e-commerce platform. Each requirement is assigned a unique identifier to enable traceability from inception through design, implementation, and User Acceptance Testing (UAT).

2. Functional Requirements

FR-01 to FR-05 — User Management

Req. IDRequirement DescriptionPriorityUSN
FR-01The system shall permit new users to register by providing a unique email address, full name, and password. Email must be validated for format correctness.Must HaveUSN-1
FR-02The system shall authenticate registered users via email and password credentials and issue a signed JWT token upon success.Must HaveUSN-2
FR-03The system shall store JWT tokens exclusively in HTTP-only cookies to prevent client-side JavaScript access (XSS mitigation).Must HaveUSN-2
FR-04The system shall enforce Role-Based Access Control (RBAC) distinguishing between the user and admin roles.Must HaveUSN-0
FR-05Authenticated users shall be able to update their profile including name, password, phone number, and saved shipping addresses.Should HaveUSN-1

FR-06 to FR-10 — Product Catalogue

Req. IDRequirement DescriptionPriorityUSN
FR-06The system shall display a paginated catalogue of products presenting name, image, description, price, rating, and stock availability.Must HaveUSN-3
FR-07The system shall provide full-text search allowing customers to query products by name and description keywords.Must HaveUSN-3
FR-08The system shall support dynamic filtering by Category, Price Range, and Average Star Rating.Must HaveUSN-3
FR-09The system shall support sorting by: Newest First, Price Ascending, Price Descending, and Highest Rated.Should HaveUSN-3
FR-10Administrators shall be able to Create, Read, Update, and Delete product records, including uploading images via Cloudinary.Must HaveUSN-8

FR-11 to FR-15 — Shopping Cart & Checkout

Req. IDRequirement DescriptionPriorityUSN
FR-11The system shall allow authenticated users to add products to a persistent shopping cart stored in MongoDB.Must HaveUSN-4
FR-12The system shall allow users to modify item quantities and remove items; the cart total shall recalculate in real time.Must HaveUSN-4
FR-13The system shall present a guided, multi-step checkout: (1) Shipping Address → (2) Payment Method → (3) Order Review & Placement.Must HaveUSN-5
FR-14The system shall integrate with a Payment Gateway (Stripe / Razorpay) to securely process card and UPI-based transactions.Must HaveUSN-6
FR-15Upon successful payment, the system shall create an order record, deduct purchased quantities from stock, and clear the user's cart.Must HaveUSN-6

3. Non-Functional Requirements

Req. IDCategoryRequirement DescriptionPriority
NFR-01SecurityAll user passwords must be hashed using Bcrypt (salt rounds ≥ 10) prior to persistence.Must Have
NFR-02SecurityAll API routes that modify data must require a valid JWT; unauthenticated requests shall return HTTP 401.Must Have
NFR-03SecurityAdmin-only routes shall apply an additional isAdmin middleware check; non-admin access returns HTTP 403.Must Have
NFR-04PerformanceProduct catalogue API responses must be returned within 500ms under normal load conditions.Should Have
NFR-05PerformanceAll product images must be served via the Cloudinary CDN to ensure sub-second image load times globally.Should Have
NFR-06UsabilityThe frontend must be fully responsive from 320px (mobile) to 1920px (desktop).Must Have
NFR-07ReliabilityMongoDB's document atomicity must ensure stock deduction and order creation are performed consistently, preventing overselling.Must Have
NFR-08MaintainabilityAll backend code must follow MVC pattern: Router → Middleware → Controller → Model. No business logic in route handlers.Should Have
NFR-09ScalabilityThe stateless JWT model shall ensure the API can be horizontally scaled without shared session state.Could Have
